# Руководство: Nintendo Switch, Персональные Смартфоны и Обход РКН
## cluster-switch-proxy & Personal Device Gateway

---

## 1. Назначение и Архитектура

Пользовательские устройства (игровая консоль **Nintendo Switch**, личные смартфоны, планшеты) сталкиваются с двумя противоположными задачами:
1. **Обход блокировок РКН / ТСПУ**: доступ к магазину Nintendo eShop, сетевым сервисам Nintendo Switch Online, Discord, YouTube, Telegram без замедлений и сбоев.
2. **Доступ к российским сервисам извне**: при нахождении за пределами РФ или на мобильных сетях с некорректной маршрутизацией — возможность выходить через проверенный чистый домашний IP РФ (СПб `188.242.33.93`).

Для этого в кластере K8s развернут сервис **`cluster-switch-proxy`** на базе легковесного демона `tinyproxy` (порт `3128`), работающий по принципу прозрачного шлюза с переключаемым апстримом.

## 2. Настройка Nintendo Switch

Для подключения Nintendo Switch к прокси-шлюзу:
1. Включите Nintendo Switch и откройте **Системные настройки (System Settings)** $\rightarrow$ **Интернет (Internet)** $\rightarrow$ **Интернет-настройки (Internet Settings)**.
2. Выберите вашу домашнюю сеть Wi-Fi и нажмите **Изменить настройки (Change Settings)**.
3. Прокрутите вниз до пункта **Настройки прокси (Proxy Settings)** и переключите на **Вкл (On)**.
4. Задайте параметры:
   - **Сервер (Server)**: IP адрес хоста в локальной сети (например, `192.168.1.x` или Tailscale IP `100.78.183.101`, если трафик маршрутизируется роутером).
   - **Порт (Port)**: `3128`.
   - **Аутентификация (Authentication)**: Выкл (Off) — прокси авторизует по белым спискам подсетей (`Allow 192.168.0.0/16`, `Allow 100.64.0.0/10`).
5. Нажмите **Сохранить (Save)** и выполните **Проверку подключения (Connect to This Network)**.

## 3. Режимы Работы и Переключение Апстрима

Конфигурация шлюза хранится в Kubernetes ConfigMap: `cluster-switch-proxy-config` в namespace `proxy`.

### 3.1. Режим по умолчанию: «Обход РКН» (Европа, DE)
В этом режиме весь трафик с консоли отправляется через немецкий сервер `de-proxy-1` (Франкфурт), минуя фильтрацию ТСПУ. eShop, обновления игр и сетевые лобби работают на максимальной скорости без потери пакетов.

Директива в `tinyproxy.conf`:
```text
Upstream http 100.111.55.54:3128
```

### 3.2. Режим: «Чистый домашний IP РФ» (СПб, RuProxy)
Используется при необходимости выхода в интернет под легитимным российским домашним адресом.

Директива в `tinyproxy.conf`:
```text
Upstream http 100.83.113.50:3128
```

### 3.3. Режим: «Орион»
Трафик направляется через шлюз проекта Orion.

Директива в `tinyproxy.conf`:
```text
Upstream http 10.244.3.196:3128
```

## 4. Будущая Интеграция: Управление через Веб-Админку

В рамках инициативы по устранению разрозненных скриптов переключение апстрима для `cluster-switch-proxy` формализуется в виде эндпоинта в Java-сервисе `service-proxy-backend`:
- `POST /api/v1/proxy/switch/mode` с телом `{"mode": "DE" | "RU" | "ORION"}`.
- На фронтенде админки (`proxy-frontend`) выводится кнопка-переключатель текущего режима в 1 клик с визуальной индикацией внешнего IP и пинга.
