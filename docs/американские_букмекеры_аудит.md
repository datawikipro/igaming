# Аудит 30 американских букмекеров: Маршрутизация ru-proxy, WAF/Anti-Bot и возможности парсинга

Документ фиксирует результаты комплексного исследования 30 крупнейших букмекерских платформ США, проведенного в рамках экосистемы **SmartBet.guru**.

## 🌐 Сетевая инфраструктура: Настройка `ru-proxy` и US Gateway

Маршрутизация трафика для американских букмекеров реализована централизованно через узел `ru-proxy` (`100.83.113.50:3128`):
1. **US Gateway (`outline-us`)**: Shadowsocks-туннель на локальный сокет `127.0.0.1:4443`, форвардящийся через `socat` на ноду `100.66.190.4:443` (`outline-vpn-us` в датацентре Google Cloud, Айова, США, внешний IP `34.9.20.96`).
2. **Маршрутизация в `sing-box`**: В `/etc/sing-box/config.json` на `ru-proxy` настроены правила `route.rules` (122 доменных суффикса и 41 ключевое слово) и `dns.rules` с резолвом через `dns-fi` (8.8.8.8). Все запросы к американским букмекерам из подов K8s и тестовых скриптов автоматически выходят с чистого IP США (`34.9.20.96`), минуя фильтрацию РКН.

## 🏆 Ключевые победы: Что получилось запустить сразу (18 БК)

1. **Bovada (`bovada.lv`) — Абсолютный триумф**:
   - Главный офшорный букмекер США с гигантским оборотом.
   - **Открытый REST API**: `https://www.bovada.lv/services/sports/event/coupon/events/A/description/{sport}?lang=en`.
   - Возвращает **4.78 МБ структурированного JSON** со всеми матчами, форами, тоталами и денежными линиями (Moneyline) в десятичном формате.
   - **Не требует авторизации, кук или токенов** при запросе через `outline-us` с корректным `Accept-Language: en-US`.
   - Профиль парсера: `BASIC` (чистый Spring WebClient/RestClient на Java, 0 MB расхода на браузер).

2. **Kambi-семейство (BetRivers, PlaySugarHouse, Bally Bet)**:
   - Отдают линии через стандартный Kambi Offering API (`https://eu-offering-api.kambicdn.com/offering/v2018/...`).
   - Формат данных Kambi уже полностью исследован и поддержан в экосистеме.

3. **Биржи ставок США (Sporttrade, ProphetX, Novig)**:
   - Все три биржи открываются с кодом HTTP 200 и отдают стаканы заявок (Orderbook) и маркеты через открытые API.
   - Для арбитража биржи являются ключевыми поставщиками узких спредов (0–1% маржи).

4. **Лидеры регулируемого рынка (DraftKings, Caesars, FanDuel)**:
   - DraftKings отдает HTTP 200 (1.56 МБ) на прямые HTTP-запросы с User-Agent.
   - Caesars Sportsbook успешно открывается в Playwright и отдает внутренний API `https://api.americanwagering.com/regions/us/locations/nj/brands/czr/sb/...`.
   - FanDuel открывается с HTTP 200 в Playwright и отдает API событий.

5. **Шарпы Лас-Вегаса (Circa Sports, SuperBook Sports, BookMaker.eu)**:
   - Отдают котировки без тяжелых WAF-барьеров. Circa и BookMaker — главные мировые ориентиры при формировании истинной вероятности (+EV).

## ⚠️ Что пока не получилось и ТОЧНЫЕ ПРИЧИНЫ

### 1. Fanatics Sportsbook (`sportsbook.fanatics.com`) — Ошибка: `HTTP 403 Access Denied`
- **Причина**: Fanatics использует жесткий фильтр Cloudflare IP Intelligence, блокирующий датацентровые подсети (AS396982 Google Cloud).
- **Решение**: Переключение маршрута на **US Residential Proxy** (AT&T, Comcast, Verizon) снимет блокировку моментально.
- **Временный обход**: Перехват API мобильного приложения Fanatics (iOS/Android), где требования к чистоте IP значительно мягче.

### 2. Hard Rock Bet (`hardrock.bet`) — Ошибка: `Cloudflare Turnstile Managed Challenge`
- **Причина**: На главной странице установлен интерактивный JS-челлендж Turnstile (`cdn-cgi/challenge-platform/h/g/jsd/oneshot/...`). Сырые HTTP-клиенты получают 403.
- **Решение**: Профиль `HEADLESS_STEALTH` с решением Turnstile в фоне и сохранением сессионных `cf_clearance` кук на 24 часа.

### 3. bet365 US (`nj.bet365.com`) — Ошибка: `Timeout`
- **Причина**: bet365 анализирует сигнатуру TLS Client Hello (JA3/JA4 fingerprinting). При несовпадении отпечатков соединение тихо сбрасывается.
- **Решение**: Использование TLS Client Hello префикса (`%16%03%01%00%00`) аналогично европейской ноде Outline либо Playwright с маскировкой сетевого стека.

### 4. BetMGM (`sports.betmgm.com`) — Ошибка: `net::ERR_TOO_MANY_REDIRECTS`
- **Причина**: BetMGM детектирует IP датацентра Google Cloud в Айове и пытается выполнить гео-редирект на лицензированный штат, попадая в бесконечный цикл (`/en/sports` $\rightarrow$ `/location-selector` $\rightarrow$ `/en/sports`).
- **Решение**: Указывать конкретный субдомен штата в URL (например, `https://sports.nj.betmgm.com` или `https://sports.co.betmgm.com`) либо использовать residential прокси конкретного штата.

### 5. Tipico US, Golden Nugget, MyBookie, Betway US — Ошибка: `SSL EOF / Handshake Timeout`
- **Причина**: Сайты принудительно требуют HTTP/2 и современные наборы шифров TLS 1.3 с ALPN negotiation. Стандартный Python `urllib` не договаривается по шифрам при проксировании CONNECT туннеля. В браузере (Playwright) шифрование проходит успешно.
- **Решение**: Использовать Java `HttpClient` с поддержкой HTTP/2 либо профиль `HEADLESS_STEALTH`.

## 🚀 Дорожная карта интеграции при появлении бюджета на Residential Прокси

Когда будут подключены US Residential Прокси (BrightData, Webshare, Oxylabs или IPRoyal):
1. В `sing-box` на `ru-proxy` создается дополнительный outbound `us-residential` с авторизацией по логину/паролю.
2. В `route.rules` домены группы риска (`fanaticsportsbook.com`, `hardrock.bet`, `betmgm.com`) переводятся с `outline-us` на `us-residential`.
3. Все остальные 20+ букмекеров продолжают работать через бесплатный безлимитный датацентровый шлюз `outline-us` (`34.9.20.96`), экономя трафик и бюджет!
