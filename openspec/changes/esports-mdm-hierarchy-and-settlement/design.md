# Design: Esports Canonical MDM Hierarchy, Discipline Reclassification & Autonomous Settlement

## Architecture & Data Model

### 1. Database Schema (`igaming_mdm`)
```sql
-- 1. Seasons
CREATE TABLE IF NOT EXISTS mdm_season (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    tournament_id BIGINT NOT NULL,
    sport_id INTEGER NOT NULL,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) NOT NULL,
    year_start INTEGER,
    year_end INTEGER,
    is_current BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT pk_mdm_season PRIMARY KEY (id, sport_id),
    CONSTRAINT fk_mdm_season_tournament FOREIGN KEY (tournament_id, sport_id)
        REFERENCES mdm_tournament (id, sport_id) ON DELETE CASCADE
);

-- 2. Season Stages
CREATE TABLE IF NOT EXISTS mdm_season_stage (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    season_id BIGINT NOT NULL,
    sport_id INTEGER NOT NULL,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) NOT NULL,
    bracket_format VARCHAR(64) DEFAULT 'SINGLE_ELIMINATION',
    stage_order INTEGER DEFAULT 1,
    is_playoff BOOLEAN DEFAULT FALSE,
    default_best_of INTEGER DEFAULT 3,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT pk_mdm_season_stage PRIMARY KEY (id, sport_id),
    CONSTRAINT fk_mdm_stage_season FOREIGN KEY (season_id, sport_id)
        REFERENCES mdm_season (id, sport_id) ON DELETE CASCADE
);

-- 3. Match Hierarchy Extension
ALTER TABLE mdm_match ADD COLUMN IF NOT EXISTS stage_id BIGINT;
ALTER TABLE mdm_match ADD COLUMN IF NOT EXISTS best_of INTEGER DEFAULT 3;
```

### 2. Multi-Sport Team Disambiguation
Organizations operating multi-discipline rosters (e.g. Team Spirit CS2 vs Team Spirit Dota 2) require dedicated rows in `mdm_team` with composite key `(id, sport_id)`:
```
Team Spirit (CS2)     -> team_id = 640592, sport_id = 33
Team Spirit (DOTA2)   -> team_id = 640592, sport_id = 34
```

### 3. Settlement Pipeline Fallback Sequence
In `MatchSettlementService.resolveConfirmedScore()`:
1. Exact fixture ID lookup in `sofascore_raw_events`
2. Canonical MDM Header status & scores
3. PostgreSQL `mdm_match` table status & scores
4. SofaScore team name fuzzy search
5. **Esports Fallback (`esports_raw_events`)**:
   - Matches discipline against `EsportsSport`
   - Queries `esports_raw_events` by `mdm_match_id` or fuzzy team match within $\pm 24\text{h}$
   - HLTV: Extracts `team1Score:team2Score` series maps
   - OpenDota: Aggregates series map wins across games via `radiantWin`
   - Links resolved match ID back to `esports_raw_events.mdm_match_id`
