# Исследование: Интеграция Азиатских Букмекерских Контор в SmartBet.guru

В данном документе приведено исследование рынка азиатских букмекерских компаний, особенности их работы, методы сбора данных (scraping/API) и план интеграции новых источников в платформу SmartBet.guru.

## 1. Анализ целевых азиатских букмекеров

Азиатские букмекеры являются ключевыми для профессиональных игроков и арбитражников из-за следующих факторов:
- **Высокие лимиты ставок** (практически не режут лимиты успешным игрокам).
- **Низкая маржа** (часто в пределах 1.5–3%, что дает высокие коэффициенты).
- **Фокус на азиатские рынки** (Asian Handicaps и Asian Totals).

| Букмекер | Популярность | Уровень лимитов | Защита от парсинга / Cloudflare | Доступность публичного API | Способ интеграции |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **SBOBET** | ⭐️⭐️⭐️⭐️⭐️ (Топ-1) | 🟢 Экстремально высокие | 🔴 Высокая (Cloudflare + Custom JS) | ❌ Нет публичного (только B2B API) | Эмуляция браузера (Playwright) / Парсинг веб-XHR |
| **Dafabet** | ⭐️⭐️⭐️⭐️ | 🟢 Высокие | 🟡 Средняя | ❌ Нет публичного | Парсинг JSON-рутов Next.js / XHR-поллинг |

## 2. Архитектурный подход к реализации

Для интеграции любого нового букмекера используется стандартная архитектурная схема платформы:
1. **Слой краулеров (`igaming-source-{bookmaker}-crawler`)**:
   - Задача: Периодический опрос линий (HTTP или WebSocket).
   - Стек: Java, Spring Boot, Playwright (через `BrowserService` для обхода Cloudflare).
   - VPN: Обязательно использование `VpnManagerService` с прокси-пулом (азиатские БК блокируют трафик из СНГ/Европы, необходимы IP-адреса Азиатского региона: Япония, Сингапур, Гонконг, Таиланд).
2. **Слой локальной БД (`igaming-source-{bookmaker}-db`)**:
   - PostgreSQL StatefulSet для локального кеширования матчей и обнаружения изменений котировок (позволяет избежать лишнего трафика в Kafka, если коэффициенты не изменились).
3. **Слой лоадеров (`igaming-source-{bookmaker}-loader`)**:
   - Задача: Чтение данных из БД, их нормализация и маппинг в общий формат `OddsUpdateRequest`, отправка в Kafka.

## 3. Особенности парсинга и обхода защит

### 3.1 SBOBET
- **Сайт**: `https://www.sbobet.com`
- **Проблема**: Защита Cloudflare + частая ротация внутренней структуры JS.
- **Решение**: Использование нашего встроенного `BrowserService` на базе Playwright. Мы можем загрузить веб-интерфейс, авторизоваться во временной сессии (или гостевом режиме) и перехватывать XHR-запросы к эндпоинту `/web-root/delivery/` или парсить DOM-дерево.

### 3.2 Dafabet
- **Сайт**: `https://www.dafabet.com`
- **Решение**: У Dafabet довольно простая система XHR запросов к спортивной платформе (часто используется платформа IBC/Maxbet). Мы можем отправлять POST-запросы к `/sports-api/` с необходимыми заголовками и региональным прокси.

## 4. План реализации на примере SBOBET

Начнем интеграцию с создания нового модуля **`igaming-source-sbobet`**.

### Шаг 1: Создание структуры папок и Maven-модуля
Создаем новый директорий `igaming-source-sbobet` со стандартной структурой:
```
igaming-source-sbobet/
├── src/main/java/pro/datawiki/igaming/source/sbobet/
│   ├── SbobetApplication.java
│   ├── config/
│   │   └── SbobetConfig.java
│   ├── scheduler/
│   │   └── MatchFetchScheduler.java
│   └── service/
│       ├── SbobetApiClient.java
│       ├── SbobetOddsMapper.java
│       └── MatchService.java
├── pom.xml
└── Dockerfile
```

### Шаг 2: Написание парсера и маппера
- **`SbobetApiClient`** будет осуществлять запросы к SBOBET, используя `BrowserService` для обхода защиты.
- **`SbobetOddsMapper`** нормализует исходы (1X2, Asian Handicap, Over/Under) в формат `OddsUpdateRequest`.
- **`MatchService`** координирует процесс, сохраняет метаданные в локальную БД и отправляет обновления в Kafka.

### Шаг 3: Написание K8s манифеста
Создаем файл `igaming-k8s/sbobet.yaml` для деплоя в k3s-кластер.
