# Proposal: [NODE PRESSURE] Перегрузка ноды xeon-srv (Memory/Disk pressure)

## Context
Plane Task ID: `2f85ea75-4d8f-4f33-9522-86b7755abca0`

## Problem Statement
Базовая bare-metal нода кластера `xeon-srv` (24 vCPU, 188 GiB RAM, 915 GiB диск, расположенная в домашних условиях в Санкт-Петербурге) подверглась критической перегрузке (Node Pressure: Memory, Disk I/O и CPU pressure):
1. **Экстремальный Load Average**: Показатели нагрузки достигали 110–140 при 24 ядрах процессора из-за одновременной работы пула из 20 AI-воркеров, 320+ подов краулеров/лоадеров и 52 баз данных PostgreSQL.
2. **Memory & Swap Pressure**: Из 188 GiB физической памяти занято свыше 128 GiB, при этом 32 GiB удерживается в `shared` памяти (`tmpfs` in-memory баз данных PostgreSQL), а файл подкачки (Swap) задействован на 3.0 GiB (37%).
3. **Задержки etcd & API Server**: Из-за насыщения очереди ввода-вывода (I/O wait) etcd периодически превышал таймауты ответа (`read tcp 127.0.0.1:44452->127.0.0.1:2379: connection timed out`), приводя к зависанию статусов подов в `ContainerStatusUnknown`.
4. **Нарушение режима тишины (22:00–10:00 МСК)**: Инцидент зафиксирован в ночное время (04:20+ МСК), когда согласно правилам AGENTS.md сервер обязан функционировать в режиме минимизации ресурсоемких операций для предотвращения раскручивания вентиляторов охлаждения до 100%.
5. **Мусорные и аварийные поды**: Наличие зависших подов (`plane-minio-c6854f96d-*` в `ContainerStatusUnknown`, `ImagePullBackOff`, `prometheus` в `ContainerStatusUnknown`), создававших паразитную нагрузку на планировщик.

## Proposed Changes
1. **Аппаратная диагностика и аудит системных метрик**:
   - Фиксация показателей Load Average, распределения RAM (used, shared/tmpfs, buff/cache, available), состояния Swap и дискового пространства overlay/rootfs.
2. **Устранение аномалий и зачистка зависших подов**:
   - Принудительное удаление зависших подов со статусами `ContainerStatusUnknown` и `ImagePullBackOff` в пространствах имен `plane` и `monitoring` (`--grace-period=0 --force`).
3. **Активация и верификация ночного профиля тишины (22:00–10:00 МСК)**:
   - Запрет неконтролируемых массовых компиляций Maven / Jib и тяжелых сборок в ночное время.
   - Ограничение параллелизма фоновых операций для снижения температуры CPU и акустического шума кулеров.
4. **Верификация неблокирующего ввода-вывода СУБД**:
   - Подтверждение политики `synchronous_commit = off` во всех StatefulSet СУБД источников для ликвидации очередей fsync на диск Xeon.
   - Проверка неблокирующих таймаутов HikariCP (`initialization-fail-timeout=0`, `connection-timeout=5000`).
5. **Верификация работоспособности сервисов и 5-минутный Soak-контроль**:
   - Контроль статуса подов в пространстве имен `igaming-dev` (`Running 1/1`, Actuator health probes `/actuator/health/readiness` и `/actuator/health/liveness` UP 200).
   - Выдерживание обязательного 5-минутного окна наблюдения за стабильностью ноды.

## Capabilities
### Modified Capabilities
- `k8s-infrastructure`: Включение требований защиты базовой ноды `xeon-srv` от Memory/Disk pressure и соблюдения ночного профиля энергопотребления (22:00–10:00 МСК).
- `verification-and-dod`: Усиление критериев приемки в условиях высокой нагрузки и ночного регламента.

## Impact
- **Нода xeon-srv**: Стабилизация Load Average, разгрузка etcd, высвобождение системных ресурсов и снижение акустического шума в ночные часы.
- **Инфраструктура K8s**: Устранение сбойных подов в `plane` и `monitoring`, обеспечение стабильного отклика Kubernetes API Server.
- **Сервисы igaming-dev**: Гарантированное сохранение доступности API, агрегатора, шлюза и ботов.
